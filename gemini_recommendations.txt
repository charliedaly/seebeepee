For an offline-first hiking app built with Jetpack Compose, the neatest and most idiomatic way to handle screen transitions between the Navigation screen and the Map screen is using Jetpack Navigation Compose, paired with a seamless Bottom Bar layout.

Since your app features a bottom toolbar (as specified in your project specs and visible in your screenshots) with persistent action icons (Start/Finish, Map/Globe, and Settings), here is the cleanest architectural pattern to achieve a fluid experience:
1. State-Driven Bottom Bar Navigation (Jetpack Compose)

Instead of complex gesture animations that might stutter or distract on outdoor devices, hiking apps benefit from instant, reliable state switching tied directly to your bottom navigation toolbar.
Implementation Structure

Define your app destinations using a sealed class or enum:
Kotlin

sealed class Screen(val route: String, val title: String, val icon: ImageVector) {
    object Navigation : Screen("nav", "Nav", Icons.Default.Navigation)
    object Map : Screen("map", "Map", Icons.Default.Public)
    object Settings : Screen("settings", "Settings", Icons.Default.Settings)
}

Then, manage the current destination in your main container using NavHost:
Kotlin

val navController = rememberNavController()

Scaffold(
    bottomBar = {
        HikeBottomBar(navController = navController)
    }
) { innerPadding ->
    NavHost(
        navController = navController,
        startDestination = Screen.Navigation.route,
        modifier = Modifier.padding(innerPadding)
    ) {
        composable(Screen.Navigation.route) {
            MainScreen(onNavigateToMap = { navController.navigate(Screen.Map.route) })
        }
        composable(Screen.Map.route) {
            MapScreen(onNavigateToNav = { navController.navigate(Screen.Navigation.route) })
        }
        composable(Screen.Settings.route) {
            SettingsScreen()
        }
    }
}

2. Recommended Transition & UX Polish

To make the transition feel native, professional, and optimized for outdoor use, consider these design adjustments:

    Zero-Lag Transitions: Avoid heavy slide-in or zoom animations between the Navigation screen and Map screen. Use instant switching or subtle crossfades (fadeIn() / fadeOut()). Outdoor users want immediate data response, not transition delays.

    Preserve State (popUpTo & saveState): When switching back and forth via the bottom bar, configure your navigation action to save the scroll position of your waypoint table and the zoom/pan state of your map canvas:
    Kotlin

    navController.navigate(screen.route) {
        popUpTo(navController.graph.findStartDestination().id) {
            saveState = true
        }
        launchSingleTop = true
        restoreState = true
    }

    Contextual Synchronization: If the user taps a specific waypoint row in the Navigation screen table, tapping it can instantly switch the view to the Map screen pre-centered on that exact waypoint, closing the loop between textual data and spatial visualization.
